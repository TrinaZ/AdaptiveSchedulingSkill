## Motivation

The main simulator is a genomics service and H8/H9 replay a batch-computing cluster. H10 adds a third service domain that matches the special issue's topic: an LLM inference service, where requests are LLM calls of two production services sharing one serving pool, and where a request's runtime is genuinely unknown at arrival because its output length is.

## Workload

Azure LLM inference trace 2023 (Patel et al., Splitwise, ISCA 2024; CC-BY): every request of a coding-assistant service (8,819) and a conversation service (19,366) on 16 Nov 2023, about one hour.

| Aspect | Setting |
|---|---|
| Real | arrival times, input (context) tokens, output (generated) tokens, service of origin |
| Synthesized | service time on one serving slot, t = 0.05 s + 0.15 ms × input tokens + 20 ms × output tokens (linear prefill + decode model; constants assumed, not measured); KV-cache footprint (input + output tokens) / 1000, held for the service time; due time (release + U[1.5,4] × estimate) and weight, as in the main benchmark |
| Estimate | prefill part exact (input length is known at arrival), decode part × U[0.6,1.4] (output length is not) |
| Tenants | coding-assistant requests are premium (weight × 3), conversation requests standard |
| Windows | the overlapping span of both services (3,424 s) split into halves: window 0 (15,106 requests) and window 1 (12,657) |
| Thinning | to the scale of one serving pool, `--thin_conc 12` (the H8 default, not tuned): every 2nd request kept by a stable hash |
| Scenes | **L0**, **L1**: each window at its average offered load (ρ = 1). **L0cap**, **L1cap**: the same windows with 30% less capacity |
| Instances | 60 consecutive requests; search from the first 20% of a window, validation 20–60%, held-out the last 40% (deployment on the future) |

## Design

Identical to H8 except for the workload.

| Aspect | Setting |
|---|---|
| Objectives | 5 SLA objectives (tard, miss, slo_wait, mix, premium), SLA texts unchanged |
| Cells | 4 scenes × 10 seeds × 5 objectives = 200 per generator |
| Instance sets | search 12, validation 1,000, held-out 60 |
| Budget | 100 |
| Generators without LLM | library, pool_full, knowledge, knowledge_tuned |
| Generators with LLM | `llm_skill` with deepseek-chat; `llm_skill@ds-reasoner` with deepseek-reasoner |
| Prompts | Unchanged, except that the pool is described as an LLM inference serving pool of a coding-assistant (premium) and a conversation service, resources as KV-cache memory, and the two request types are named |

**What we looked at before freezing.** Only a no-LLM headroom probe (`llm_probe.py`, the H8 probe with the new scene names): library and literature rules on 3 seeds × 4 scenes. On held-out instances the worst library rule costs 13% (premium) to 158% (slo_wait) more than the best, so scheduling matters on this traffic.

## Hypotheses (same tests as H8, `h8_analysis.py`)

**H10a (governance, confirmatory).** For each of knowledge_tuned, llm_skill and llm_skill@ds-reasoner: the gated violation rate (paired t gate) is ≤ 5% of cells, and ungated violations exceed gated violations (exact McNemar test, one-sided, α = 0.05).

**H10b (standard LLM).** llm_skill vs knowledge_tuned, two-sided Wilcoxon on rel. Prediction from H6 and H8b: no difference. Reported as an estimate.

**H10c (reasoning model, confirmatory).** llm_skill@ds-reasoner < knowledge_tuned, one-sided Wilcoxon on rel, α = 0.05.

**Reported without a claim.** EB-gate violations, pool_full, the per-objective breakdown (`per_objective.py` conventions), and the random-gate control of H9.
